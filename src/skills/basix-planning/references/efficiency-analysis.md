# Optional material efficiency analysis

Root explicitly decides whether analysis is required, normally at dispatch.
For `foo-001.md`, its exact adjacent companion is
`foo-001_efficency_analysis.md`: preserve this spelling and full numbered basename.
A companion is not a numbered plan. Root must explicitly grant write ownership
for exact plan/report paths, including `.basix/`; read-only context permission
never grants writes, and read-only specialists remain read-only.

Before dispatch, root resolves any existing report through explicitly authorized
update/merge or preservation, retaining material findings and task/cycle
attribution. Never overwrite another artifact or invent a suffix. Archive or
replace plan and companion together, preserving both basenames; check both
destination collisions before moving either. Respect ignore rules. Requested
analysis is an authorized artifact, not a file solely for handoff.

Analyze only material evidenced negative drivers and substantial reusable
improvements: cause, evidence, effect on work, intervention, likely benefit and
uncertainty, and practical verification. Include positive factors only when they
support a substantial reusable improvement. Use lightweight existing logs and
attributable telemetry, never broad rollout ingestion or new monitoring to fill
a report. Metrics cover only the assigned task/cycle and eligible descendants;
separate agent/tool execution from parent waiting/review and human delay. Never
invent tokens, timing, baselines or causality. Session-only totals cannot establish
task waste or be allocated by guess; mark unavailable/confounded metrics honestly.

Reuse attribution guidance in
[basix-subagent-efficiency](../../basix-subagent-efficiency/SKILL.md) and evidence
rules in [basix-experience](../../basix-experience/SKILL.md), without invoking their
independent full-report formats. If no substantial finding is evidenced, say so
concisely; no filler. Failed attempts still require requested analysis. A later
request needs an explicit bounded authorized assignment or context-related
continuation under Contract 2.0, with explicit report write access. Unchanged-target
compaction restores checkpoint state; changed verification targets require a newly authorized
frozen cycle under Contract 2.0.
