## Proposed domain contract and bounded policies

Root must accept or explicitly revise these values/choices in R-BIND; they are proposed benchmark fixtures, not external facts. All command inputs include tenant, supplied occurred/logical time, generated identities, policy/tariff version and deterministic tie-break inputs. Stable canonical encoding includes explicit integer/unit/currency representations and sorted object keys/effect order; reject unsupported values and pin engine format/policy versions. No service, DB/network, wall clock or RNG import in engine. Exactly one E18 implementation is linked by all five adapters.

Tenant validation precedes business reads; explicit tenant predicates and tenant-bearing primary/foreign/unique keys supplement fail-closed DB policy. D05 sets transaction-local tenant context and clears/verifies it on success, exceptions and pool return. Transactions lock bounded aggregate/stock rows in stable order, never a tenant-wide queue lock. Stock source revisions are authoritative for observed physical quantity; inventory accepted stock/version is authoritative for available capacity. Reservation records own reserved capacity/epoch/lifecycle; execution's committed dispatch admission owns consumption once admitted. A timeout or stale reservation event is not proof that admitted capacity is releasable. Execution terminal state is authoritative for terminal shipment outcome; immutable ledger rows own money truth. Conflicting observations enter bounded reconciliation, not last-arrival overwrite.

Reserve/cancel/expire/admit uses expected revisions and tenant-scoped stable reservation IDs, explicit expiry input, monotonically increasing fencing epochs and an atomic conditional admission/consumption handshake in the shared transaction adapters. New dispatch requires epoch authority. Validate/renew via allocation's contract endpoint; execution admission transaction conditionally checks the current reservation epoch/lifecycle in shared storage, so a stale validation cannot race expiry into a double release. No service implementation imports another. Allocation request -> execution and execution validate/renew -> allocation are bounded contract calls; allocation validation never calls execution synchronously. Dispatch result is asynchronous and queryable by stable key. Services boot independently with bounded readiness/degraded checks; retry/pending state replaces an unbounded startup callback chain. Stock and shipment propagation use outbox/inbox. Allocation/execution form a runtime cycle only; builds remain a DAG.

Admission writes a durable dispatch identity/epoch before any carrier operation. Carrier lookup by that identity precedes retry after ambiguity. Worker claims have fencing epochs; DB conditional writes reject stale owners, and the fictional simulator must atomically enforce/validate current fencing authority at the carrier action boundary, including pause after the last local check. If the simulator cannot provide that boundary, fail the safety gate and resolve the protocol before acceptance; a pre-call DB check alone cannot prove an old holder never acts. Ledger posting uses unique tenant + authoritative terminal fact + tariff identity, balanced integer minor units within one currency; corrections append linked compensating postings without modifying originals. Late cancellation always follows this correction path.

A committed applicable command atomically writes aggregate revision + canonical accepted journal + inbox receipt + outbox effects. Broker acknowledgment follows commit; publishing follows commit. Each envelope includes tenant, event ID, producer, aggregate ID/version, schema revision, causation ID, correlation ID, occurred time; retry preserves all identities. Receipt uniqueness and payload digest distinguish duplicates from conflicting identity reuse. Gaps queue per aggregate until verified predecessors/reconciliation; never apply a dependent event out of order or fabricate stock. No distributed exactly-once or global order claim.

Proposed retry policy: maximum 8 attempts AND 120 seconds since first attempt; exponential backoff starts 100ms, cap 5s, injected deterministic jitter seed recorded outside pure engine; stop when either budget expires. DB deadlock subretry maximum 3 attempts/2 seconds within the parent budget; lock wait maximum 100ms in the declared fairness fixture. Poison/conflicting identities quarantine immediately; exhausted records retain tenant, original IDs, causation, reason and budgets. Audited redrive requires authorized operator/reason and original identity, re-enters the same business guards; poison cannot block the entire partition. Reconciliation batches maximum 100 aggregate items, 30 seconds per pass, 3 passes/5 minutes total then durable needs-attention; other aggregates/tenants continue. Outbox claims and worker leases last 15 seconds, renewal every 5 seconds with fenced conditional ownership; bounded per-tenant scheduling quantum 10 jobs, global round-robin fixture, never unlimited hot-tenant lock monopolization. Recovery budgets and clocks are test-injected.

Snapshot includes tenant/aggregate, engine format, policy lineage, exact journal boundary and cryptographic digest. Verify boundary continuity/digest before trusting snapshot, otherwise verify a complete journal fallback; if neither verifies, stop only the affected aggregate visibly. Replayed effect identities must match, but external dispatch/charge is gated by durable dispatch receipts/ledger uniqueness, never blindly re-executed from emitted replay effects. Proposed journal cleanup waits 30 days AND verified snapshot lineage plus all inbox/outbox/recovery cursors and financial/audit retention obligations; keep anything still needed even past 30 days. Do not infer a legally sufficient retention period; product/operations must decide it before deployment.

Proposed mixed-version rollout: 24-hour rollback window after backfill validation and new release health; source translation jobs use the same 100-item/30-second/3-pass budgets and explicit unresolved quarantine. Restore rehearsal uses a named backup digest and verifies tenant/version/journal/ledger lineage. Before cleanup the old binary can roll back against additive schema, with accepted compatibility evidence. After cleanup only forward recovery or verified restore plus journal/outbox/carrier/ledger reconciliation is allowed, never promised old-binary rollback. Unresolved product choices: tariff/version catalog, correction authorization and tax rounding, allowed unit conversions, supported legacy revision translations and irreconcilable-record policy, production retry/fairness SLOs, retention/legal requirements, restore RPO/RTO and deployment/rollback windows. Benchmarks use explicit fixture choices; unresolved deployment choices block production release, not unrelated component work.
